## ES-DE Sync v1.8.0

### 새 기능

- `_UNREGISTERED Duplicate Manager`: 관리 ROM이 Android canonical 위치에 존재하고 source·canonical·관리 원본 SHA가 일치하는 중복을 안내합니다. 자동 삭제하지 않으며 사용자가 체크한 항목만 처리합니다.
- `SAFE_DELETE`는 추가 보존 데이터가 없는 중복을 정리합니다. `SAFE_MERGE_DELETE`는 검증된 `.srm/.rtc/.state` migration과 메타데이터 병합을 먼저 완료한 뒤 중복 ROM을 삭제합니다. 관리 ROM은 유지됩니다.
- 격리 실기기에서 두 경로와 migration 후 인게임 save 인식 및 Save State 표시·Load·저장 장면 복귀를 확인했습니다.

### 진행률 UI

- 전체 진행률, 현재 단계, 처리 개수, 현재 파일과 경과 시간을 표시합니다.
- 총량을 모르는 구간은 marquee로 표시하고 완료 시 determinate 표시로 전환합니다. DuplicateScan 진행 표시와 완료 summary 숫자를 실기기 GUI에서 확인했습니다.

### 성능 개선

- 동일 실기기·동일 데이터의 **읽기 전용 planning**: 135.533초 → 18.144초(86.6% 단축), ADB 호출 1470 → 44.
- media compare: 83.325초 → 2.497초. DuplicateScan은 기존 83.989초에서 실제 GUI 목록 표시 12.751초로 개선됐습니다.
- 별도의 **실제 GUI no-op sync 전체 시간**은 45.990초였습니다. planning 시간과 전체 sync 시간은 측정 범위가 다릅니다.
- batch inventory/SHA, 필요한 항목의 hashing, session-local memo 및 snapshot 재사용을 적용했습니다. persistent cache와 병렬 처리는 사용하지 않습니다.

### 메타데이터와 안전성

- Android runtime 태그의 존재 여부와 0/empty 값을 보존하며 folder metadata를 일반 gamelist merge에서 보존합니다.
- `_TEST`는 Duplicate Manager에서 완전히 제외합니다. REVIEW 보호, media HOLD, mutation 직전 검증, 전용 journal/recovery gate와 Dropbox read-only 정책을 유지합니다.
- progress/status와 기존 sync summary 계약을 유지합니다. no-op XML은 fresh snapshot 검증 후 전송을 생략합니다.

### 알려진 제한

- REVIEW_ONLY는 선택하거나 자동 정리할 수 없습니다.
- local media, slot/autostate, save/state 목적지 충돌, custom/unknown metadata, 다중 후보·경로 모호성 및 지원 근거가 없는 환경은 REVIEW입니다.
- slot/autostate와 media migration은 지원하지 않습니다. 실패 journal은 보존하며 자동 rollback/resume하지 않습니다.

### 검증

- 전체 회귀, PowerShell 5.1 syntax/BOM, 실제 v1.4.8 validator 및 App 8/package 13 계약을 검증합니다.
- 실기기 no-op sync에서 ROM/XML/save/state/media와 Dropbox 변경 0, 최종 SAFE 2회를 확인했습니다.
